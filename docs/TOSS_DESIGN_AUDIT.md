# TOSS DESIGN AUDIT — RiskFit 웹 MVP 적용 기준서

> 본 문서는 RiskFit 웹 MVP가 토스(Toss, viva republica) 수준의 미니멀하고 신뢰감 있는 UI/UX를 갖추기 위한 **공식 기준**이다. 후속 에이전트(설계·구현·critique·QA)는 이 문서를 단일 진실의 원천(Single Source of Truth)으로 삼아야 한다. 문서에 명시된 헥스값·픽셀값·ms 값은 협상 대상이 아니다.

---

## 1. 토스 디자인 철학 5원칙

토스 앱이 수많은 핀테크 경쟁자를 압도하는 이유는 정교한 그래픽 때문이 아니라, 다음 다섯 가지 원칙을 어떤 화면에서도 흔들림 없이 지키기 때문이다. RiskFit은 보험·건강이라는 더 무거운 도메인을 다루므로 이 원칙은 더욱 엄격하게 적용되어야 한다.

### 원칙 1. 한 화면, 한 생각 (One Screen, One Job)
한 화면은 정확히 하나의 의사결정 또는 하나의 입력만 요구한다. 사용자가 "지금 내가 뭘 해야 하지?"라고 0.3초 이상 고민하게 만들면 이미 실패다.
- **RiskFit 반례**: 기본정보 화면에서 성별·연령·키·체중·직업·흡연·음주를 **한 화면에 모두 펼치는 것**은 토스 위반이다. 토스는 이걸 7단계로 쪼갠다. 우리는 최소 3단계(기본/건강/생활)로 분리한다.

### 원칙 2. 여백이 콘텐츠다 (Whitespace as Content)
빈 공간은 낭비가 아니라 정보다. 토스는 한 화면의 60% 이상을 비워둔다. 여백이 압축되는 순간 사용자는 "복잡하다 = 어렵다 = 위험하다"고 느낀다.
- **RiskFit 반례**: 결과 화면에서 위험점수·BMI·흡연·음주·가족력을 **카드 5개로 빽빽이 채우는 것**은 토스 위반이다. 점수 카드 하나만 화면의 절반을 차지해야 한다.

### 원칙 3. 숫자가 주인공 (Numbers Are the Hero)
핀테크의 신뢰는 숫자에서 나온다. 숫자는 항상 가장 크고, 가장 진하고, 가장 먼저 보여야 한다. 설명은 숫자 아래에 작게.
- **RiskFit 반례**: "당신의 위험점수는 36점입니다"라고 한 줄로 처리하는 것은 토스 위반이다. **"36"** 이라는 숫자만 48px Bold로 먼저 보이고, "점 (낮은 위험)"이 그 아래 14px로 따라붙어야 한다.

### 원칙 4. 친근하지만 격식 있다 (Casual but Trustworthy)
토스의 톤은 친구가 알려주는 듯 친근하면서도, 돈을 맡겨도 될 만큼 단단하다. "확인" 같은 차가운 단어 대신 "네, 알겠어요"를 쓴다. 그러나 "야 잠깐만" 같은 과도한 친근함은 금지.
- **RiskFit 반례**: "당신은 위험합니다" → 위협적이라 토스 위반. "위험해요 ㅠㅠ" → 가벼워서 토스 위반. 정답은 **"지금 건강 신호가 평균보다 조금 높아요"**.

### 원칙 5. 마찰을 줄여라 (Reduce Friction Relentlessly)
한 번이라도 사용자가 멈칫하면 그 자리에서 이탈한다. 키패드는 자동으로 뜨고, 다음 입력은 자동으로 포커스되고, 단위(kg, cm, 세)는 placeholder가 아니라 입력칸 옆에 고정 표시한다.
- **RiskFit 반례**: 체중을 입력하라면서 "kg"을 placeholder로 두는 것은 토스 위반이다. 사용자가 입력을 시작하면 placeholder가 사라져 단위가 보이지 않게 된다. 단위는 **입력칸 오른쪽에 고정 텍스트**로 항상 노출되어야 한다.

## 2. 컬러 토큰

토스 컬러는 **블루 1색 + 9단계 그레이 + 시맨틱 3색**으로 충분하다. 더 늘리면 토스가 아니다.

### Primary — Toss Blue

| 토큰 | Hex | 용도 |
|---|---|---|
| `--blue-500` | `#3182F6` | Primary CTA, 활성 상태, 강조 |
| `--blue-600` | `#1B64DA` | Primary CTA hover/pressed |
| `--blue-400` | `#4593FC` | Primary CTA disabled-tint, 보조 |
| `--blue-50`  | `#E8F3FF` | Selected/Focus 배경 틴트 |

토스는 순수 검정(#000)을 절대 쓰지 않는다. 가장 진한 텍스트도 `#191F28`이다.

### Semantic

| 토큰 | Hex | 용도 |
|---|---|---|
| `--success` | `#1AC788` | 낮은 위험, 정상, 완료 |

## 3. 타이포그래피 스케일

폰트는 **Pretendard Variable** 단일. 시스템 폰트 fallback은 `-apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, sans-serif`.

### Weight 운용 원칙
- 본문은 **Regular 400**, 라벨/보조 강조는 **Medium 500**, 카드 제목·버튼은 **Semibold 600**, 숫자 디스플레이·페이지 제목은 **Bold 700**, **Extrabold 800은 큰 숫자(48px 이상)에만** 쓴다.

### Type Scale

| 토큰 | Size / Line Height | Weight | Letter Spacing | 용도 |
|---|---|---|---|---|
| `display` | 48px / 56px | 800 Extrabold | -0.03em | **위험점수 "36"**, 큰 금액 |
| `h1` | 32px / 40px | 700 Bold | -0.02em | 페이지 타이틀 (Landing 헤드라인) |
| `h2` | 24px / 32px | 700 Bold | -0.02em | 화면 질문 ("기본정보를 알려주세요") |
| `h3` | 20px / 28px | 600 Semibold | -0.01em | 카드 타이틀 |
| `h4` | 18px / 26px | 600 Semibold | -0.01em | 섹션 헤더 |
| `body-lg` | 17px / 26px | 400 Regular | 0 | **입력 폰트**, 본문 강조 |
| `body` | 15px / 22px | 400 Regular | 0 | 일반 본문 |
| `caption` | 13px / 18px | 500 Medium | 0 | 라벨, 메타 정보 |
| `micro` | 11px / 14px | 500 Medium | 0.02em | 면책, 법적 고지 |

### RiskFit 결과 화면 — "36점" 명시 규칙

- 숫자 **"36"**: `display` 토큰, **48px / Extrabold 800 / `--gray-900` / tabular-nums / letter-spacing -0.03em**
- 단위 "점": 숫자 옆에 `h3` (20px / Semibold / `--gray-700`)
- 등급 라벨 "낮은 위험": 숫자 아래 `caption` (13px / Medium / 등급 색상)
- 변경 폭(증감) 표시는 숫자 오른쪽 위 첨자처럼 `body` 크기로 색만 의미색.

```css
.score-display {
  font-family: 'Pretendard Variable', sans-serif;
  font-size: 48px;
  line-height: 56px;
  font-weight: 800;
  letter-spacing: -0.03em;
  color: var(--gray-900);
  font-variant-numeric: tabular-nums;
}
```

## 4. 여백 & 그리드

토스 spacing은 **4px 단위**. 8px, 12px, 16px, 20px, 24px, 32px, 40px, 48px, 64px이 자주 쓰인다. 6px·10px·14px·18px·22px 같은 **non-4 배수는 금지**.

### Spacing Token

| 토큰 | 값 | 주된 용도 |
|---|---|---|
| `space-1` | 4px | 아이콘-텍스트 갭 |
| `space-2` | 8px | 인라인 요소 갭 |
| `space-3` | 12px | 버튼 내부 패딩 (vertical) |
| `space-4` | 16px | 입력 필드 간 갭 |
| `space-5` | 20px | 카드 내부 섹션 갭 |
| `space-6` | 24px | **카드 padding 표준** |
| `space-8` | 32px | 카드 간 갭 |
| `space-10` | 40px | 섹션 사이 큰 갭 |
| `space-12` | 48px | 페이지 상하 패딩 |
| `space-16` | 64px | 큰 영웅 영역 |

### 페이지 그리드
- 모바일: 좌우 padding **20px** 고정. 콘텐츠 max-width 없음.
- 데스크탑/태블릿: 콘텐츠 max-width **480px** (모바일 폭 시뮬레이션). 화면 가운데 정렬, 양 옆은 `--gray-50` 배경.
- 한 페이지의 세로 리듬: `48px (top) → 콘텐츠 → 24px → CTA → 24px (bottom safe area)`.

### 카드 padding 규칙
- 단일 카드: **`padding: 24px`** (`space-6`).
- 카드 내부 섹션 분리: `margin-bottom: 20px` (`space-5`).
- 한 카드에 정보는 **하나의 사실**만. 위험점수 카드에 BMI까지 끼워 넣지 않는다. BMI는 별도 카드.

## 5. 모서리 · 그림자 · 고도(Elevation)

### Radius

| 토큰 | 값 | 적용 |
|---|---|---|
| `radius-sm` | 8px  | 칩, 작은 배지 |
| `radius-md` | 12px | **버튼, 입력 필드** |
| `radius-lg` | 16px | **카드** |
| `radius-xl` | 20px | 모달, 바텀시트 상단 |
| `radius-full` | 9999px | 원형 아바타, 토글 |

원형(`50%`)은 아바타에만. 버튼은 **절대 pill 형태를 쓰지 않는다** (radius 12px 사각형).

### Shadow / Elevation

토스 그림자는 거의 보이지 않는다. 카드는 그림자 대신 **1px solid `--gray-200`** 보더에 의존하기도 한다.

| 토큰 | 값 | 적용 |
|---|---|---|
| `elev-0` | 그림자 없음, border `1px solid var(--gray-200)` | 리스트 카드, 일반 카드 |
| `elev-1` | `0 1px 3px rgba(0, 0, 0, 0.04)` | 살짝 떠 있는 카드 |
| `elev-2` | `0 4px 12px rgba(0, 0, 0, 0.06)` | 바텀시트, 토스트 |
| `elev-3` | `0 12px 32px rgba(0, 0, 0, 0.08)` | 모달, 드롭다운 |

> **금지**: `0 4px 8px rgba(0,0,0,0.2)` 같은 강한 그림자, 머티리얼 디자인의 `elevation-8` 이상. 절대 안 된다.

## 6. 모션

### Timing Function
- 기본: `cubic-bezier(0.4, 0, 0.2, 1)` (ease-out 변형)
- 강조: `cubic-bezier(0.34, 1.56, 0.64, 1)` (살짝 튀는 spring)

### Duration

| 시나리오 | Duration | Easing |
|---|---|---|
| 버튼 hover/press | **150ms** | ease-out |
| 입력 포커스 보더 색 전환 | **120ms** | ease-out |
| 카드 등장 (페이드+8px 슬라이드업) | **240ms** | ease-out |
| 페이지 전환 (좌→우 슬라이드) | **300ms** | ease-out |
| 토스트 등장 | **280ms** | spring |
| 토스트 소멸 | **200ms** | ease-in |
| 모달 등장 | **320ms** | ease-out |
| 숫자 카운트업 (점수 36 표시) | **800ms** | ease-out |
| 진행률 바 채워짐 | **600ms** | ease-out |

### 핵심 규칙
- 100ms 미만 모션은 없다 → 사용자가 변화를 인지하지 못한다.
- 400ms 초과 모션은 없다 → 답답함을 유발한다.
- 모션은 한 번에 **두 속성까지만** (예: opacity + translateY). 셋 이상 동시 변화는 산만하다.
- `prefers-reduced-motion: reduce` 대응 필수. duration을 1ms로 떨군다.

## 7. 마이크로카피

토스 톤 룰:
- **반말 금지, 과한 존댓말 금지**. "~해요" 끝맺음 기본.
- 사용자에게 의무를 부과하는 명령형 금지. "입력하세요" → "알려주세요".
- 부정적·위협적 표현 금지. "위험" 대신 "신호", "오류" 대신 "다시 한 번 확인해 주세요".
- 숫자·고유명사는 따옴표 없이 본문 안에 자연스럽게 녹인다.

### RiskFit 5개 안내 문구 — 토스 톤 다시 쓰기

| 상황 | 일반적인(나쁜) 문구 | **토스 톤 문구** |
|---|---|---|
| 동의 화면 | "본 서비스 이용을 위해 약관에 동의해 주십시오." | **"시작하기 전에 두 가지만 동의해 주세요."** |
| 결과 시작 | "분석이 완료되었습니다. 결과를 확인하세요." | **"분석이 끝났어요. 결과를 함께 살펴볼게요."** |
| 리포트 시작 | "리포트를 생성합니다. 잠시만 기다려주세요." | **"30초만 시간을 주세요. 리포트를 만들고 있어요."** |
| 입력 검증 실패 | "잘못된 값입니다." | **"숫자를 다시 한 번 확인해 주세요."** |
| 면책 | "본 서비스는 의료적 진단을 대체하지 않습니다." | **"이 결과는 참고용이에요. 의료적 진단은 의사 선생님과 상의해 주세요."** |

CTA 버튼 문구는 동사보다 **사용자의 다음 행동**을 적는다.
- "확인" → **"네, 알겠어요"**
- "다음" → **"다음으로"**
- "제출" → **"분석 시작하기"**
- "닫기" → **"닫기"** (이건 토스도 그냥 닫기)

## 8. 컴포넌트별 토스 패턴

### 8.1 버튼

| 속성 | 값 |
|---|---|
| Primary 배경 | `--blue-500` (#3182F6) |
| Primary 텍스트 | `#FFFFFF` |
| Hover | `--blue-600` (#1B64DA), 150ms |
| Pressed | `scale(0.98)` + `--blue-600`, 100ms |
| Disabled | `--gray-200` 배경 / `--gray-500` 텍스트 |
| Height | **56px** (h-14) — 풀 와이드 CTA 표준 |
| Radius | **12px** |
| Font | 17px / Semibold 600 |
| 위치 | 하단 고정 (`position: sticky; bottom: 20px`) |

Secondary 버튼은 배경 `--gray-100`, 텍스트 `--gray-800`. 토스에는 **outlined 버튼이 거의 없다** — 보더 있는 버튼은 약해 보이기 때문이다.

한 화면에 **primary CTA는 1개**. Secondary는 보조 행동 (예: "나중에 할게요").

### 8.2 입력 필드

| 속성 | 값 |
|---|---|
| 라벨 위치 | **입력칸 위** (placeholder-as-label 금지) |
| 라벨 폰트 | 13px / Medium / `--gray-700` |
| 입력 폰트 | **17~18px** / Regular / `--gray-900` |
| 보더 | 1px solid `--gray-300` |
| Focus 보더 | **2px solid `--blue-500`** (120ms 전환) |
| Radius | 12px |
| Height | 56px |
| Padding | `0 16px` |
| 단위 표시 | 입력칸 **오른쪽 고정 텍스트**, `--gray-600`, 15px |
| 에러 보더 | 2px solid `--danger` |
| 에러 메시지 | 입력칸 아래 13px / `--danger` |

라벨이 입력 폰트보다 작은 것은 토스 패턴이다(라벨 13px, 입력 17px). 반대로 라벨이 입력보다 크면 토스 위반.

### 8.3 카드

| 속성 | 값 |
|---|---|
| 배경 | `#FFFFFF` |
| Radius | **16px** |
| Padding | **24px** |
| 보더 | `1px solid --gray-200` (또는 무 보더) |
| 그림자 | `elev-0` 또는 `elev-1` (`0 1px 3px rgba(0,0,0,0.04)`) |
| 카드 간 갭 | 12px (밀착 리스트) 또는 16px |

한 카드 = 한 사실. 점수 카드, BMI 카드, 흡연 카드, 음주 카드를 **분리**한다.

### 8.4 탭

언더라인이 두꺼우면 토스가 아니다. 토스 탭은 두 가지 패턴 중 하나:

**(A) 텍스트 탭** (대시보드/상세/리포트/체크 같은 콘텐츠 탭)
- Active: 텍스트 `--gray-900` / Semibold 600 / 아래에 **2px / 24px wide / `--gray-900`** bottom indicator
- Inactive: 텍스트 `--gray-500` / Medium 500 / indicator 없음
- 전환: 200ms ease-out, indicator의 `transform: translateX`로 슬라이드

**(B) 칩(chip) 탭** (필터, 카테고리)
- Active: 배경 `--gray-900` / 텍스트 `#FFFFFF`
- Inactive: 배경 `--gray-100` / 텍스트 `--gray-700`
- Radius: **9999px** (칩만 pill 허용)
- Height: 36px / Padding `0 14px`

탭 자체에 컬러(파랑)를 쓰는 것은 토스 위반. 액티브는 **흑백 대비**로 표현한다.

### 8.5 숫자 디스플레이

| 속성 | 값 |
|---|---|
| 폰트 | Pretendard Variable |
| Size | **48px (display)** 또는 36px / 32px |
| Weight | **Extrabold 800** |
| Color | `--gray-900` |
| Letter Spacing | `-0.03em` |
| `font-variant-numeric` | **`tabular-nums`** (필수, 자릿수 정렬) |
| 단위 | 숫자 옆 20px / Semibold / `--gray-700` |
| 증감 표시 | 별도 줄, 14px / Medium, 색은 의미색 (`--success`/`--danger`) |

숫자에 그라데이션이나 색을 넣는 것은 토스 위반이다. 숫자는 검정, 의미는 옆 라벨/배지로.

## 9. RiskFit 화면별 토스화 가이드

### 9.1 Landing
화면 상단 64px 여백 후 24px 일러스트(또는 없음), 그 아래 `h1` 32px Bold로 **"건강 신호를 30초 만에 확인하세요"**. 본문 `body` 15px `--gray-700`로 한 문장 보조. 화면 하단 고정 Primary CTA "지금 시작하기" 한 개. 다른 링크는 캡션 13px로 CTA 아래 중앙 정렬 "이미 분석한 적 있어요 →" (Secondary text link). **로그인 강요 금지, 마케팅 배너 금지.**

### 9.2 InputBasic (기본정보)
화면 상단 ProgressBar (얇은 2px, `--blue-500`, 1/7 표기), 그 아래 `h2` "기본정보를 알려주세요" + `body` 보조 한 줄 "정확할수록 결과가 정확해져요". 입력 필드는 **세로로 한 칸씩**: 성별(세그먼트 컨트롤 — 칩 두 개), 연령(숫자 키패드 자동, 단위 "세"), 키(cm), 체중(kg). 각 입력 간 갭 16px. 하단 고정 Primary "다음으로" — 모든 필드 채워지면 활성화, 아니면 `--gray-200` 배경 비활성.

### 9.3 InputHealthLifestyle (건강·생활)
같은 레이아웃 패턴. 흡연/음주 같은 단일 선택은 **세그먼트 컨트롤**(칩형 탭), 빈도는 **슬라이더 대신 칩 그리드 3개**("주 1~2회", "주 3~4회", "주 5회 이상"). 슬라이더는 토스가 거의 안 쓴다 — 값 입력 불확실성 때문이다. 운동량은 라디오 카드 3장 세로 배치. 카드 선택 시 `--blue-50` 배경 + `--blue-500` 2px 보더.

### 9.4 InputFamilyHistory (가족력 카드)
"부모님이나 형제자매 중에 다음 질환을 가진 분이 있나요?"를 `h2`로. 질환별 카드 리스트 — 카드마다 "있어요 / 없어요 / 모르겠어요" 칩 3개. **체크박스 그리드는 토스 위반** — 너무 빽빽하다. 각 카드는 `padding: 20px`, 카드 간 12px 갭, 답변 미선택 카드는 살짝 더 진한 보더로 "아직 답하지 않음" 시그널.

### 9.5 InputInsurance (보험 다건)
"가입한 보험을 알려주세요" `h2`. 처음엔 빈 상태 (Empty state) — 가운데 회색 일러스트 + "아직 등록된 보험이 없어요" + Secondary 버튼 "보험 추가하기". 추가하면 카드가 위에서 슬라이드다운 (240ms)으로 추가. 각 카드는 좌상단 보험사명 `h4`, 우상단 삭제 아이콘(탭 시 200ms 페이드아웃), 본문 상품명·납입액·만기. 카드 우하단 "수정" 텍스트 링크. 하단 고정 Primary "다음으로", 그 위에 Secondary outline 없는 "+ 보험 추가" 버튼.

### 9.6 Analyzing (분석 중)
화면 정중앙 단 하나의 요소: **회전하는 진행 인디케이터**(원형, 48px, `--blue-500`) + 그 아래 24px 간격 `h3` "잠시만요, 분석하고 있어요" + 13px caption "최대 10초 정도 걸려요". 진행 메시지를 1.5초마다 교체 ("건강 신호 계산 중", "유사 사례 비교 중", "리포트 준비 중") — fade-cross 200ms. **하단 CTA 없음, 취소 버튼 없음**. 분석이 멈춘 듯 보이지 않도록 ProgressBar는 indeterminate 패턴.

### 9.7 Result (대시보드/상세/리포트/체크)
상단 Sticky 탭바 (텍스트 탭 A 패턴), 4개: "대시보드 · 상세 · 리포트 · 체크". 활성 탭만 `--gray-900` + bottom indicator.

- **대시보드**: 최상단 카드는 거대한 점수 카드 — 카드 안에 `display` 48px "36" + 옆에 "점" 20px + 아래 13px "낮은 위험". 카드 padding 32px, radius 16px. 그 아래 16px 갭으로 BMI/흡연/음주/운동 4개 작은 카드 2x2 그리드 (모바일에선 1열). 각 작은 카드는 라벨 13px + 숫자 24px + 등급 배지.
- **상세**: 각 위험 요인을 카드 한 장씩, 위에서 아래로. 카드 안에 요인명 `h3` + 한 줄 설명 `body` + "왜 이런 결과인지" 토글(170ms 펼침). 토글 펼침 영역엔 모델 근거 2~3줄과 참고 통계.
- **리포트**: PDF 미리보기 썸네일 한 장 + 그 아래 Primary "PDF로 받기" 버튼 1개. 다른 옵션 없음. 다운로드 시 200ms 토스트 "리포트가 저장되었어요".
- **체크**: 액션 아이템 리스트. 각 아이템은 체크박스 + 한 줄 텍스트 + 우측 캡션("이번 주"/"이번 달"). 완료 시 체크박스가 `--blue-500`로 채워지며 텍스트에 strikethrough 150ms.

## 10. 체크리스트 (Anti-pattern Detector)

후속 에이전트와 critique 라운드에서 각 화면을 평가할 때 사용한다. **하나라도 해당하면 토스 위반 → 수정 필수.**

| # | 검사 항목 | 판정 |
|---|---|---|
| 1 | 한 화면에 Primary CTA가 2개 이상이다 | 위반 |
| 2 | 라벨 폰트(13px)가 입력 폰트(17px+)보다 작지 않다 | 위반 |
| 3 | 버튼 height가 56px 미만이다 | 위반 |
| 4 | 버튼이 pill(radius 9999px) 형태다 (칩 제외) | 위반 |
| 5 | 카드 그림자가 `rgba(0,0,0,0.1)` 이상 진하다 | 위반 |
| 6 | 숫자 디스플레이에 그라데이션·컬러가 들어갔다 | 위반 |
| 7 | 4의 배수가 아닌 spacing(예: 14px, 18px)이 쓰였다 | 위반 |
| 8 | 컬러 팔레트에 정의되지 않은 색(예: 보라, 분홍)이 등장한다 | 위반 |
| 9 | 검정(#000)이나 흰색 위 흰색이 쓰였다 | 위반 |
| 10 | placeholder를 라벨 대신 쓴 입력 필드가 있다 | 위반 |
| 11 | 단위(kg, cm, 세)가 placeholder에만 있고 입력 후 사라진다 | 위반 |
| 12 | 마이크로카피가 "확인", "제출", "취소"처럼 명령형이다 | 위반 |
| 13 | 한 카드에 정보가 2개 이상의 사실로 묶여 있다 | 위반 |
| 14 | 모션 duration이 100ms 미만이거나 400ms 초과다 | 위반 |
| 15 | 탭 활성 표시에 파랑 배경/언더라인 두께 4px 이상이 쓰였다 | 위반 |
| 16 | `font-variant-numeric: tabular-nums`가 숫자 디스플레이에 빠졌다 | 위반 |
| 17 | 페이지 콘텐츠가 화면 폭 480px를 넘어 펼쳐진다 (데스크탑) | 위반 |
| 18 | 위험·경고 색이 점수 숫자 자체에 적용되었다 | 위반 |

### 적용 우선순위 (후속 작업 가이드)

1. **컬러·타이포 토큰**을 CSS 변수로 먼저 박는다 (섹션 2, 3).
2. 모든 화면의 **여백·spacing**을 4의 배수로 재정비 (섹션 4).
3. **버튼·입력·카드** 컴포넌트를 토스 패턴으로 일괄 교체 (섹션 8).
4. **마이크로카피**를 섹션 7 룰로 다시 쓴다.
5. 각 화면을 섹션 9의 가이드에 맞춰 재구성.
6. 마지막으로 섹션 10 체크리스트로 전수 감사. 위반 0건이 되어야 릴리스.

> 본 기준서를 따르지 않은 디자인은 RiskFit MVP에 진입할 수 없다. 이견이 있다면 본 문서를 먼저 개정한 뒤 작업한다.
